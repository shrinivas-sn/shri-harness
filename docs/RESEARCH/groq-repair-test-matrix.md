## 5. Fixture and harness design (for Task 11.2)

- **One loopback fixture per script**, `listen(0, "127.0.0.1")`, with separate routes: `/openai/v1/chat/completions`, `/openai/v1/models`, and the catalog URL. Unknown paths → 404 and a recorded failure. Bodies stay in memory; the report carries booleans and counts only.
- **Strict mode** on chat: 400 for assistant `reasoning_content`, unsupported `reasoning_effort`, or `include_reasoning` outside GPT-OSS 120B/20B (mirrors `E:\dev-recipes\_knowledge\cache\groq-reasoning-controls.md`). Every reply streams `reasoning` deltas before content.
- **Markers:** each turn's prompt asks for a unique token; the fixture echoes it back. Completion is detected only after the prompt-echo position (GR-02).
- **Waits:** launch ≤20 s (existing), dialogs ≤10 s, turns ≤30 s, `/models` stall test ≤10 s for the notice, exit ≤5 s. A longer wait needs measured timings (PLAN Failure handling).
- **Seeded history (GR-07):** written as a synthetic store file under the disposable `SHRI_DIR` before launch, distinct marker text from new turns so old and new history are distinguishable.
- **Cleanup ownership:** each script owns its fixture servers and PTY (`finally`: Ctrl+C ×2, `waitForExit`, `close`); `smoke-installed.ts` owns temp roots via `removeTemporary`. Record the PTY PID and its children at launch; fail on survivors. No process sweeps.
